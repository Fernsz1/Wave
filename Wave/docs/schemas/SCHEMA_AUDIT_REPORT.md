## 1. Executive Summary

The wire **codec layer itself is healthy**: [codec.py](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/server/wave_api/codec.py) and [codec.ts](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/Wave/src/protocol/codec.ts) are faithful, line-for-line mirrors driven entirely by [wire_manifest.json](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/protocol/wire_manifest.json) — there is no positional drift between Python and TS encode/decode. Most snake_case ↔ camelCase renames (`grade_level→gradeLevel`, `teacher_id→teacherId`, `topic_id→topicId`, etc.) are correctly and consistently handled in [derive.py](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/server/wave_api/derive.py) / [ingest.py](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/server/wave_api/ingest.py).

The real problems are **above and below** the codec — in (a) what the four schema layers each choose to carry for the same logical field, and (b) two components that bypass the shared `httpRepository`/`schemas` mapping and roll their own, incorrectly:

- 🔴 **One confirmed runtime bug shipped today:** [RemediationWizard.tsx](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/Wave/src/components/RemediationWizard.tsx#L183-L194) posts `topicId`/`studentLrn` to `/api/remediation/generate`, but [views.py](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/server/wave_api/views.py#L142-L147) reads `originalTopicId`/`studentName`. Every AI generation through this wizard (a mounted, reachable component — see [App.tsx](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/Wave/src/App.tsx)) silently runs with an empty topic and the literal string `"your class"`.
- 🔴 **One confirmed cross-subject data leak:** `RemediationMaterial.subject` is stored in the DB but never placed on the `TeacherRemediationMaterial` wire payload. `targetSubject` on the frontend type is therefore always `undefined` for any server-sourced material, and [StudentLessons.tsx](file:///C:/Users/Luis/OneDrive/Desktop/CeView%20UID/Wave/Wave/src/components/StudentLessons.tsx#L721-L724)'s subject filter (`!m.targetSubject || m.targetSubject === activeSubject`) treats `undefined` as "matches every subject" — remedial summatives published for Mathematics will appear under Science and English tabs too.
- 🔴 Several fields are computed by the frontend, threaded carefully through call sites, and then **silently dropped one hop before the wire** (`QuizAttempt.lesson_id`, real `failedItems` on summative results).
- 🟡 Real, but non-breaking: duplicated mapping logic (AI-response shaping, and **[NEW]** the `TeacherRemediationMaterial` wire→internal mapping exists twice, verbatim, in the same file), one DB field exposed under two different wire names (`total` vs `perfectScore`), and **[NEW]** one model that gets inconsistently populated depending on which of two ingest code paths last touched it.
- 🟢 The static catalog (`Lesson`/`Topic`/`QuizQuestion`) round-trips cleanly through all four layers with no drift.
- 🟢 Minor: plaintext PINs and teacher passwords are returned by the unauthenticated `GET /api/roster` endpoint to support client-side login fallback — flagged as a security note, not a schema defect.

Overall health: **alignment is good at the codec/rename level, but weak at the "what does each layer actually choose to include" level** — five fields exist in the DB/wire with no living frontend consumer, and two fields the UI needs are missing from the wire shape it's typed against.
